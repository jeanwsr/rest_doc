# Derivatives of the Becke Partition Weights in DFT

This document discusses the derivatives of the Becke partition weights up to second order. For now, we do not discuss the contributions to the first- or second-order DFT derivatives arising from the grid shift (grid-shift) involving the Becke partition.

In previous discussions, we generally assumed that the grids are sufficiently complete. This holds in quite a few scenarios (hybrid GGA frequency and thermodynamic analyses, spectroscopy calculations, and so on). For meta-GGA tasks, however, the introduction of the kinetic-energy density leads to rather severe numerical errors; this amplifies the impact of grid incompleteness (in turn causing frequency errors of several hundred cm<sup>-1</sup>, whereas under GGA these rarely exceed 5 cm<sup>-1</sup>).

To improve the numerical problems caused by grid incompleteness under meta-GGA, or in some special LDA/GGA scenarios (such as AIMD with special accuracy requirements), it is necessary for us to consider the derivative contributions induced by the grid shift.

The derivative contributions of the grid shift generally consist of two parts: **the grid weights** and **the grid coordinates**. Of these, the former requires the derivatives of the grid weight $w_g$ with respect to the atomic coordinates. This document will focus on this problem. REST currently implements the Becke partition, which is also the most commonly used partition method in computational chemistry programs; we restrict the discussion to this method.

## 1. Architecture of the Becke partition derivative program

**This architecture design was completed jointly by human and AI** (it came out of an AI refactor, once the initial human-AI hybrid code was working).

:::{admonition} Implementation decision: the pseudo-SIMD type `f64simd` based on fixed-length arrays
:class: note

In the concrete program implementation, we split the grid dimension $g$ in two ways: a thread-parallel task split (`nbatch`, taken as 1024 in the Hessian program, and it must be a multiple of the lane length), and a serial SIMD lane split within each thread (8).

The rationale for this decision is

- In modern languages, if the pseudo-SIMD type implements operator overloading for +/-/*/div etc., the program implementation differs little from that for the ordinary floating-point type f64.
- The implementation details of the Becke grids involve rather intricate code; if one does not explicitly use arrays of the SIMD lane length but instead loops over individual floats, the compiler will not necessarily perform reasonable automatic vectorization.

Points to note

- This type is pseudo-SIMD, not true SIMD. Compiler options such as `target-cpu=v3/v4/native` are needed to realize the performance advantage of SIMD; but this also means that CPUs of other microarchitectures may be unable to execute the binary.

This design pattern is also quite common in the C code of PySCF.
:::

To balance considerations such as computational performance, memory reuse, and the code length of individual functions, the current program is somewhat intricate at the framework level. The types involved in the whole computation fall into
- **Main-thread-level interface**
  - Preprocessing (pub `BeckeMolTables`), responsible for computations that involve atoms only (interatomic distances and their derivatives, Radii adjustment factors, etc.). This part of the code must be completely decoupled from the grid batching process, to avoid repeated loop computations or memory copies over the grids.
  - User parameter input (pub `BeckePartitionArg`) and output (pub `BeckePartitionOutput`). The input parameters determine how many derivative orders to take and whether to perform fused-contraction.
  - Computation settings (`BeckePartitionContext`), used to record dimension information, the derivative order, references to input vector data, scratch space for output results, and so on.
- **Thread-parallel-level interface**
  - Task splitting (`BatchTask`), which splits all grids into mutually non-overlapping intervals $[g_0, g_1)$. Task boundaries are determined by the grid ownership scheme (`AtmIndices`): under `ByGrid`, the split is uniform with the fixed `nbatch` (a task may internally mix grids of different atoms); under `ByAtom`, tasks do not cross the grid-interval boundaries of atoms, and each task corresponds to a single atom only.
  - Thread buffers (`TaskBuffers`), allocated once by the per-worker initialization of the parallel iterator and reused by all subsequent tasks of that worker thread. These comprise the contraction partial sums (`TaskContraction`) and the lane scratch (`LaneScratch`). The contraction partial sums are reduced into the output buffer under a mutex at the end of each task.
- **Grid-iteration-level interface**
  - Lane gathering (`gather_lane_batch`, outputting `LaneBatch`), which reorganizes the task's grid batch into pseudo-SIMD lanes of fixed length (`SIMDD` = 8). This function is the bridge between the thread-parallel level and the grid-iteration level.
  - Lane evaluation and write-back (the `eval_*`/`store_lane_*` function families dispatched by `process_lane`, together with `LaneScratch`, `LanePartition`, `LaneAttrib`, etc.), which, taking a single lane (8 grids) as the unit, complete the evaluation of all requested derivative orders, the write-back to the output buffers, and the accumulation into the contraction partial sums.

The call relationship between the three levels is: the entry function builds `BeckeMolTables` and `BeckePartitionContext`, splits out `BatchTask`s and hands them to rayon for parallel iteration; each task is first gathered into a `LaneBatch`, and then `process_lane` is executed lane by lane. Apart from a few types and entry functions of the main-thread-level interface (pub `BeckeMolTables`, `BeckePartitionArg`/`BeckePartitionOutput`, `AtmIndices`, and the entry functions), all other types are private implementation details.

## 2. Original definition and program implementation of the Becke partition

### 2.1 The concept of grid partition

We denote by $A, B, M$ atomic indices, and by $g$ the grid index.

| Variable | Formula | Meaning | Dims | Owner |
|--|--|--|--|--|
| `weights`, `w` | $w_g$ | Grid weight | $(g)$ | `LanePartition`<br>`BeckePartitionOutput` |
| `wquad`<br>`quadrature_weights` | $w_g^\text{quad}$ | Quadrature weight | $(g)$ | input |
| `P` | $P_{Mg}$ | Becke partition | $(M, g)$ | `LaneScratch` |
| `Z` | $Z_M$ | Becke partition sum | $(M)$ | `LanePartition` |
| `Pg` | $\bar{P}_{g}$ | Becke partition of the atom corresponding to the grid | $(g)$ | `LanePartition` |

The grid weight is written $w_g$; here $g$ is the grid index, and its corresponding 3-component ($x, y, z$) spatial grid coordinate is $\boldsymbol{r}_g$. **The grid weight $w_g$ is a function of the nuclear coordinates $\boldsymbol{R}_A, \boldsymbol{R}_B, \ldots$**. Grid weights should in general satisfy the following property:

$$
\sum_{g} w_g f(\boldsymbol{r}_g) \simeq \int d\boldsymbol{r} f(\boldsymbol{r}) \quad \forall f(\boldsymbol{r})
$$

In the program implementation, the grid weight $w_g$ is a combination of the quadrature weight $w_g^\text{quad}$ and the Becke partition $P_{Mg}$:

$$
w_g = w_g^\text{quad} \frac{\bar{P}_{g}}{Z_g}
$$

- The raw grids mean that current DFT grids are always generated as spherical grids centered on each atom, usually Lebedev grids. The weights of these Lebedev grids are precisely $w_g^\text{quad}$. Ideally, the Lebedev grids (and their weights) at each atomic center would be complete; in practical computations, however, such grids can hardly strike a balance between exact completeness and performance. A sensible approach is therefore to first generate complete Lebedev grids at each atomic center, and then to combine these grids into a single global grid through the Becke partition. In this way the number of grids can be reduced while accuracy is preserved.
- **A grid $g$ is always a Lebedev grid generated by some atom $M$**. $\bar{P}_g$ is defined here as $\sum_{M} P_{M g} \delta_{g \in M}$, i.e., the value of the Becke partition for the atom $M$ corresponding to the grid $g$.
- The Becke partition $P_{Mg}$ is the (unnormalized) partition coefficient of atom $M$ for grid $g$. Normalization is carried out through $Z_g = \sum_{M} P_{Mg}$.

### 2.2 Concrete implementation of the Becke partition

| Variable | Formula | Meaning | Dims | Owner |
|--|--|--|--|--|
| `adjustment_factor` | $a_{AB}$ | Radii adjustment factor | $(A, B)$ | `BeckeMolTables` |
| `grid_coords`, `coords` | $\boldsymbol{r}_g$, $r_{g t}$ | Grid coordinates | $(g, 3)$ | input |
| `atm_coords` | $\boldsymbol{R}_A$, $R_{A t}$ | Nuclear coordinates | $(A, 3)$ | `BeckeMolTables` |
| `dist` | $\Vert r \Vert_{Ag}$ | Distance between nucleus and grid | $(A, g)$ | `LaneScratch` |
| `atm_dist` | $\Vert R \Vert_{AB}$ | Internuclear distance | $(A, B)$ | `BeckeMolTables` |
| `mu` | $\mu_{A B g}$ | Ellipsoidal coordinate difference | | temporary |
| `s` | $s_{A B g}$ | Switch function | | temporary |
| `P` | $P_{Mg}$ | Becke partition | $(M, g)$ | `LaneScratch` |
| `Z` | $Z_M$ | Becke partition sum | $(M)$ | `LanePartition` |
| `Pg` | $\bar{P}_{g}$ | Becke partition of the atom corresponding to the grid | $(g)$ | `LanePartition` |

The program implementation of the Becke partition lives in `eval_partition`; however, some important intermediate quantities that are independent of the grids must be computed before entering the Becke partition. These include

- **Radii adjustment factor `adjustment_factor` $a_{AB}$**. Note that it is usually an antisymmetric matrix. There are different types of methods for computing the Radii adjustment; REST adopts the original Becke adjustment strategy, see eq (A3)-(A6) of the Becke 1988 paper. In REST this quantity is computed automatically by `gen_adjustment_factor` from the Bragg radii corresponding to the nuclear charges, so users need not construct it manually (the grid generation part of REST is based on dftlibs/numgrid).
- **Internuclear distance `atm_dist` $\Vert R \Vert_{AB}$**. It is obtained from the 2-norm of the nuclear coordinates (`BeckeMolTables::new`, c.f. `fn dist3_naive`):

  $$
  \Vert R \Vert_{AB} = 
  \begin{cases}
  \sqrt{\sum_t (R_{B t} - R_{A t})^2} & A \neq B \\
  \infty & A = B
  \end{cases}
  $$

After entering the function `eval_partition`, the operations to perform include

- **Nucleus-grid distance `dist` $\Vert r \Vert_{Ag}$**. It is obtained from the 2-norm of the nuclear coordinates and the grid coordinates (c.f. `fn dist3_hybrid`):

  $$
  \Vert r \Vert_{Ag} = \sqrt{\sum_t (r_{g t} - R_{A t})^2}
  $$

- **Ellipsoidal coordinate difference `mu` $\mu_{A B g}$**; this variable is an intermediate quantity, iterated over in the $(A, B)$ double loop:

  $$
  \mu_{A B g} = \frac{\Vert r \Vert_{Ag} - \Vert r \Vert_{Bg}}{\Vert R \Vert_{AB}}
  $$

- **Switch function intermediate `f3` $f_3 (\mu)$** (c.f. `fn switch_f3`, `fn switch_f_hardness`):

  $$
  \begin{aligned}
  f_3 (\mu) &= p \circ p \circ p \circ \nu (\mu) && \text{(eq. 20)} \\
  p (\nu) &= \frac{3}{2} \nu - \frac{1}{2} \nu^3 && \text{(eq. 19)} \\
  \nu (\mu) &= \mu + a (1 - \mu^2) && \text{(eq. A2)}
  \end{aligned}
  $$

- **Switch function `s` $s_{A B g}$** and **Becke partition `P` $P_{Ag}$**.

  $$
  \begin{aligned}
  s_{A B g} &= \frac{1}{2} (1 - f_3 (\mu_{A B g})) && \text{(eq. 21)} \\
  P_{A g} &= \prod_{B \neq A} s_{A B g} && \text{(eq. 13)}
  \end{aligned}
  $$
  
  In the actual program implementation, the results of the switch function are contracted directly into the Becke partition rather than stored separately. Meanwhile, exploiting the $\text{antisymm}(A, B)$ property, the computational work here can be halved. Therefore, the actual program proceeds by first initializing $P_{A g}$ to 1 and iterating only over $0 = B < A = n_\mathrm{atom}$:

  $$
  \begin{aligned}
  s_{A B g} &= \frac{1}{2} (1 - f_3 (\mu_{A B g})) \\
  s_{B A g} &= \frac{1}{2} (1 + f_3 (\mu_{A B g})) \\
  P_{A g} &\mathrel{\times}= s_{A B g} \\
  P_{B g} &\mathrel{\times}= s_{B A g}
  \end{aligned}
  $$

- **Becke partition sum `Z` $Z_g$**. It is the normalization factor of the Becke partition:

  $$
  Z_g = \sum_{M} P_{M g} \tag{eq. 22}
  $$

- **Becke partition of the atom corresponding to the grid `Pg` $\bar{P}_g$**. It is the Becke partition $P_{M g} \delta_{g \in M}$ corresponding to the atom $M$ that generated the Lebedev grid for grid $g$. In the actual program implementation, two cases must be distinguished:
  - If the atoms of the Lebedev grids corresponding to the grid points are in arbitrary order (corresponding to PySCF's default option `sort_grids=True`), the `LaneAttrib::ByGrid` path is taken, and the grid-atom mapping table `atm_idx` is used to select the values of $P_{M g}$ into $\bar{P}_g$.
  - If all grids in a lane batch are guaranteed to belong to one fixed atom (corresponding to PySCF's `sort_grids=False`, or the current grid organization of REST), the `LaneAttrib::ByAtom` path is taken. This is also the recommended approach, which in particular helps considerably in the subsequent DFT derivatives.

- **Grid weight `w` $w_g$**. This is the grid weight after the Becke partition has been completed, and it is also used in all computational tasks involving DFT grid integration:

  $$
  w_g = w_g^\text{quad} \frac{\bar{P}_{g}}{Z_g} \tag{eq. 22}
  $$

## 3. The switch function $f(\nu)$ and its derivatives

We first deal with a rather special problem: the switch function $f(\nu)$ and its derivatives.

:::{admonition} Implementation decision: specialization of the $f_3(\nu)$ implementation
:class: note

In the original formula, $f_3(\nu) = p^n(\nu)$; the power here means function composition, not a numerical power. But almost all programs implement the case $n = 3$. Therefore, we dispatch to a specialized $f_3$ implementation, while other cases recurse.
:::

The implementation of this part is rather mechanical; when necessary, simply check the source code. Note that the function here is $f(\nu)$, with $\nu$ as the independent variable. Writing out the terms one by one (the derivatives of $p$):

$$
\begin{aligned}
p' (\nu) &= \frac{3}{2} (1 - \nu^2) \\
p'' (\nu) &= -3 \nu
\end{aligned}
$$

Let $f_0 = \nu$, $f_i = p (f_{i-1})$, and $g_i = p' (f_{i-1})$. By the chain rule,

$$
f_3' = g_2 g_1 g_0, \qquad f_3'' = -3 \big[ f_2 (g_1 g_0)^2 + f_1 g_2 g_0^2 + \nu g_2 g_1 \big]
$$

The form of $f_3''$ comes from applying the product rule to each layer of composition: each layer contributes a term of the $p'' (f_{i-1}) \, (\ldots)^2$ type, and $p'' = -3x$ makes the coefficient exactly $-3 f_{i-1}$. For arbitrary hardness, the program does not expand this formula, but recurses layer by layer (with initial values $f_0 = \nu$, $f_0' = 1$, $f_0'' = 0$):

$$
f_{k+1} = p (f_k), \qquad f_{k+1}' = p' (f_k)\, f_k', \qquad f_{k+1}'' = p'' (f_k)\, (f_k')^2 + p' (f_k)\, f_k''
$$

During the recursion, $f_{k+1}''$ must be computed first from the old values, then $f_{k+1}'$ and $f_{k+1}$ (c.f. `switch_d2nu_f_hardness`).

The switch function itself is the composition $s = s_3 \circ \nu$ with $\mu$ as the independent variable (eq. A1/A2). The derivatives of $\nu$ with respect to $\mu$ are

$$
\nu' = 1 - 2 a \mu, \qquad \nu'' = -2 a
$$

Therefore, the first and second derivatives of $s$ with respect to $\mu$ are

$$
\begin{aligned}
\frac{\partial s}{\partial \mu} &= -\frac{1}{2} f_3' \nu' \\
\frac{\partial^2 s}{\partial \mu^2} &= -\frac{1}{2} f_3'' (\nu')^2 - \frac{1}{2} f_3' \nu''
\end{aligned}
$$

According to the half-iteration convention of Section 2.2, for the same $\mu_{ABg}$, the $\mu$-derivatives of all orders of $s_{ABg} = \frac{1}{2} (1 - f_3)$ and $s_{BAg} = \frac{1}{2} (1 + f_3)$ differ by exactly a sign.

The subsequent derivations (Sections 5.1, 6.1) use logarithmic derivatives. $s_{\text{safe}}$ replaces $s$ as the denominator (the clamping is explained in Section 5.1):

$$
\frac{\partial \log s}{\partial \mu} = \frac{1}{s_{\text{safe}}} \frac{\partial s}{\partial \mu}, \qquad \frac{\partial^2 \log s}{\partial \mu^2} = \frac{1}{s_{\text{safe}}} \frac{\partial^2 s}{\partial \mu^2} - \left( \frac{\partial \log s}{\partial \mu} \right)^2
$$

## 4. Translational invariance of the gradient problem

We first introduce one more notation: a grid $g$ is always a Lebedev grid generated by some atom; we denote this generating atom by $A_g$, and write $g \in A_g$ for “$g$ is a grid generated by atom $A_g$”.

In the subsequent derivations, we will treat the grid coordinates $\boldsymbol{r}_g$ as independent variables that do not depend on any nuclear coordinates $\boldsymbol{R}_A$. **From the program's point of view, this is wrong**. In an actual program, when we rebuild the grids starting from an atom whose coordinates have been perturbed, the grid coordinates change with the atomic coordinates: a grid $g \in A_g$ translates rigidly with its generating atom $A_g$. Therefore, in principle the derivatives of the grid coordinates with respect to the atomic coordinates must of course be considered; if they are ignored, the analytical derivatives of many intermediate quantities will not match the numerical derivatives.

Once the dependence of the grid coordinates on the atomic coordinates is introduced, however, the derivation and computation become complicated. Our strategy is: **from now on, forget the dependence of $\boldsymbol{r}_g$ on $\boldsymbol{R}_{A_g}$, until the final evaluation of the derivatives of $w_g$, at which point the method of this section is applied as a uniform correction**. The correction relies on the invariance of the grid weights under overall translation; after this treatment, the final results agree with numerical derivatives, even though the intermediate quantities cannot be verified against numerical derivatives.

The dependence structure deserves a case-by-case discussion. Since $\boldsymbol{r}_g$ depends only on $\boldsymbol{R}_{A_g}$ and not on the coordinates of the other atoms:

- For $A \neq A_g$: $\boldsymbol{r}_g$ does not vary with $\boldsymbol{R}_A$; the partial derivatives computed as if $\boldsymbol{r}_g$ were independent are the true derivatives, and the results are correct.
- For $A = A_g$: the partial derivatives computed as if $\boldsymbol{r}_g$ were independent are wrong; the true derivative is the total derivative, which can be inferred from the correct partial derivatives with respect to the other atoms:

$$
\frac{\mathrm{d} w_g}{\mathrm{d} R_{A_g t}} = - \sum_{M \neq A_g} \frac{\partial w_g}{\partial R_{M t}} \quad (g \in A_g)
$$

The left-hand side of the above equation is the total derivative; the partial derivatives on the right-hand side are all computed under the “$\boldsymbol{r}_g$ independent” convention. We now derive the above equation.

First, we treat the nuclear coordinates and the grid coordinates simultaneously as independent variables, writing

$$
w_g = w_g (\boldsymbol{r}_g, \boldsymbol{R}_A, \boldsymbol{R}_B, \ldots)
$$

The grid weight is translationally invariant: applying one and the same translation $\boldsymbol{t}$ to all coordinates leaves the grid weight unchanged,

$$
w_g (\boldsymbol{r}_g + \boldsymbol{t}, \boldsymbol{R}_A + \boldsymbol{t}, \boldsymbol{R}_B + \boldsymbol{t}, \ldots) = w_g (\boldsymbol{r}_g, \boldsymbol{R}_A, \boldsymbol{R}_B, \ldots)
$$

Taking the total derivative with respect to $\boldsymbol{t}$ of both sides at $\boldsymbol{t} = \boldsymbol{0}$, we obtain

$$
\frac{\partial w_g}{\partial \boldsymbol{r}_g} + \sum_M \frac{\partial w_g}{\partial \boldsymbol{R}_M} = 0
$$

Now consider $g \in A_g$, and seek the derivative of $w_g$ with respect to the generating atom's coordinates $\boldsymbol{R}_{A_g}$. Neither the Lebedev angular grids nor the radial grids rotate with the nuclear coordinates (the grid definition has no orientational dependence); after $\boldsymbol{R}_{A_g}$ is translated by $\boldsymbol{t}$, $\boldsymbol{r}_g$ is translated by $\boldsymbol{t}$ as well. Stated mathematically (the identity matrix below is 3×3),

$$
\frac{\mathrm{d} \boldsymbol{r}_g}{\mathrm{d} \boldsymbol{R}_{A_g}} = \mathbf{I}
$$

Hence the total derivative of $w_g$ with respect to $\boldsymbol{R}_{A_g}$ is

$$
\frac{\mathrm{d} w_g}{\mathrm{d} \boldsymbol{R}_{A_g}} = \frac{\partial w_g}{\partial \boldsymbol{R}_{A_g}} + \frac{\partial w_g}{\partial \boldsymbol{r}_g} \mathbf{I} = \frac{\partial w_g}{\partial \boldsymbol{R}_{A_g}} + \frac{\partial w_g}{\partial \boldsymbol{r}_g}
$$

Substituting $\frac{\partial w_g}{\partial \boldsymbol{r}_g} = - \sum_M \frac{\partial w_g}{\partial \boldsymbol{R}_M}$ as given by translational invariance, we obtain

$$
\frac{\mathrm{d} w_g}{\mathrm{d} \boldsymbol{R}_{A_g}} = \frac{\partial w_g}{\partial \boldsymbol{R}_{A_g}} - \sum_M \frac{\partial w_g}{\partial \boldsymbol{R}_M} = - \sum_{M \neq A_g} \frac{\partial w_g}{\partial \boldsymbol{R}_M}
$$

Taking its $t$ component gives the correction formula stated earlier, and the derivation is complete.

Looking back at the whole argument, we used only two facts: the explicit variable set of $w_g$ is $(\boldsymbol{r}_g; \boldsymbol{R}_A, \boldsymbol{R}_B, \ldots)$, and $w_g$ is invariant under overall translation. The argument does not depend on the concrete functional form of the Becke partition, so it holds equally for other grid partition schemes, and even for gradient computations of more general “quantities carried along with the grids”. The generating atom of a grid $g$ is the only atom that must be treated with total derivatives; the partial derivatives with respect to all other atoms are correct to begin with. Therefore, in the program implementation, all partial derivatives can first be computed under the “$\boldsymbol{r}_g$ independent” convention, and the total derivative for the generating atom is finally inferred via the correction formula.

:::{note}
**Additional remark: translational-invariance correction for second derivatives**

The correction of the second derivative $\partial^2 w_g / \partial R_{A t} \partial R_{B s}$ follows the same principle; but since each of the two derivative indices $A$ and $B$ may individually fall on the generating atom, three types of summation formulas must be distinguished: rows ($A = A_g$), columns ($B = A_g$), and the corner ($A = B = A_g$). We defer the details to the chapter discussing second-order gradients.
:::

## 5. Program implementation of the Becke partition first-order gradients

The first-order gradients are implemented in the program in two steps. The first step (the first-order gradient part of `eval_switch_pair_pass`, Section 5.2) accumulates, per atom pair and building on the zeroth-order quantities ($P_{M g}$, $\Vert r \Vert_{A g}$, $Z_g$, $\bar P_g$, etc.; see Section 2.2), two 3-dim intermediate derivative quantities $\frac{\partial Z_g}{\partial R_{At}}$ and $\frac{\partial \bar P_g}{\partial R_{At}}$. The second step (`eval_lane_dw`, Section 5.3) performs the quotient-rule final evaluation of $w_g = w_g^{\text{quad}} \bar P_g / Z_g$, together with the translational-invariance correction of Section 4.

Among these, the derivative of the running product $P_{Mg}$ is the first nontrivial problem in the derivation; we explain it separately in Section 5.1.

### 5.1 Derivatives of the running product $P_{Mg}$

Applying the product rule directly to the running product would produce an expansion with $O(n_\mathrm{atom})$ terms, each containing $n_\mathrm{atom} - 1$ factors; the customary treatment is to take the logarithm of the running product, turning the product into a sum. Taking the logarithm of both sides of eq. 13,

$$
\log P_{Mg} = \sum_{N \neq M} \log s_{MNg}
$$

then differentiating,

$$
\frac{\partial P_{Mg}}{P_{Mg}} = \partial \log P_{Mg} = \sum_{N \neq M} \partial \log s_{MNg}
$$

and rearranging, we obtain the basic formula for the derivative of the running product:

$$
\partial P_{Mg} = P_{Mg} \sum_{N \neq M} \partial \log s_{MNg}
$$

This form has two advantages.

- **Numerical stability**: $P_{Mg}$ and its derivatives appear only as multiplicative factors; $P_{Mg}$ never enters a denominator. The Becke partition can be extremely small at grids far from atom $M$, and division by $P_{Mg}$ would amplify relative errors. By contrast, the $1 / s$ appearing in $\partial \log s$ is bounded: the program applies a lower-bound clamp to overly small $s$ ($s_{\text{safe}} = \max(s, 10^{-14})$, c.f. `INVTOL`).
- **Contraction structure**: what is actually needed later (Section 5.3) is not the 4-dim tensor $\frac{\partial P_{Mg}}{\partial R_{At}}$, but its two contractions $\frac{\partial Z_g}{\partial R_{At}} = \sum_M \frac{\partial P_{Mg}}{\partial R_{At}}$ and $\frac{\partial \bar P_g}{\partial R_{At}} = \frac{\partial P_{A_g g}}{\partial R_{At}}$, both of them 3-dim tensors $(A, t, g)$. With the formula above, the accumulation can proceed per atom pair, without ever explicitly constructing any $(M, A, t, g)$ intermediate tensor.

Another key structural fact is that $s$ is a unary function of $\mu$, so the tensor $s_{MNg}$ has derivatives only with respect to its own paired $\mu_{MNg}$:

$$
\frac{\partial s_{MNg}}{\partial \mu_{ABg}} = \frac{\partial s_{MNg}}{\partial \mu_{MNg}} \delta_{AM} \delta_{BN}
$$

Combining with the chain rule, the derivative of $P_{Mg}$ with respect to the atomic coordinates is

$$
\frac{\partial P_{Mg}}{\partial R_{At}} = P_{Mg} \sum_{N \neq M} \frac{\partial \log s_{MNg}}{\partial \mu_{MNg}} \frac{\partial \mu_{MNg}}{\partial R_{At}}
$$

The explicit expression for the switch function logarithmic derivative $\frac{\partial \log s}{\partial \mu}$ is given in Section 3 and will not be expanded here.

| `dmu_log_sA` | $\partial \log s_{ABg} / \partial \mu_{ABg}$ | Switch logarithmic derivative | | temporary |
| `dmu_log_sB` | $\partial \log s_{BAg} / \partial \mu_{ABg}$ | Switch logarithmic derivative (opposite side) | | temporary |
| `dR_Z` | $\partial Z_g / \partial R_{At}$ | First derivative of the normalization factor | $(A, t, g)$ | `LaneScratch` |
| `dR_Pg` | $\partial \bar P_g / \partial R_{At}$ | First derivative of the grid partition numerator | $(A, t, g)$ | `LaneScratch` |

This subsection corresponds to the first-order gradient part of `eval_switch_pair_pass`. The operations to perform include

- **Grid distance derivative `dR_dist` $\Vert \partial r \Vert_{Atg}$**. It is the derivative with respect to $R_{At}$; geometrically, it is the $t$ component of the unit vector pointing from the grid to atom $A$:

  $$
  \Vert \partial r \Vert_{Atg} := \frac{\partial \Vert r \Vert_{Ag}}{\partial R_{At}} = \frac{R_{At} - r_{gt}}{\Vert r \Vert_{Ag}}
  $$

- **Interatomic distance derivative `dR_atm_dist` $\Vert \partial R \Vert_{ABt}$**. It is grid-independent and is precomputed in `BeckeMolTables` (when deriv $\geqslant 1$):

  $$
  \Vert \partial R \Vert_{ABt} := \frac{\partial \Vert R \Vert_{AB}}{\partial R_{At}} = \frac{R_{At} - R_{Bt}}{\Vert R \Vert_{AB}}
  $$

  Note that it is antisymmetric in $(A, B)$: $\Vert \partial R \Vert_{ABt} = - \Vert \partial R \Vert_{BAt}$, i.e., it changes sign when the derivative is taken with respect to the atom on the right.

- **Role derivatives of the ellipsoidal coordinate `dR_mu_roleA`/`dR_mu_roleB`**. The true derivative tensor $\frac{\partial \mu_{MNg}}{\partial R_{At}}$ is 5-dim, $(A, M, N, t, g)$, but it contains Kronecker deltas:

  $$
  \frac{\partial \mu_{MNg}}{\partial R_{At}} = \frac{\partial \mu_{ANg}}{\partial R_{At}} \delta_{AM} + \frac{\partial \mu_{MAg}}{\partial R_{At}} \delta_{AN}
  $$

  In the actual computation the deltas are contracted away in advance: the differentiating atom is either the left endpoint of $\mu$ (role A) or its right endpoint (role B), so only two 3-component temporaries are needed per pair $(A, B)$:

  $$
  \begin{aligned}
  \frac{\partial \mu_{ABg}}{\partial R_{At}} \; (\text{role A}) &= \frac{1}{\Vert R \Vert_{AB}} \big( \Vert \partial r \Vert_{Atg} - \mu_{ABg} \Vert \partial R \Vert_{ABt} \big) \\
  \frac{\partial \mu_{ABg}}{\partial R_{Bt}} \; (\text{role B}) &= \frac{1}{\Vert R \Vert_{AB}} \big( -\Vert \partial r \Vert_{Btg} + \mu_{ABg} \Vert \partial R \Vert_{ABt} \big)
  \end{aligned}
  $$

- **Per-atom-pair accumulation `dR_Z`/`dR_Pg`**. Following the half-iteration convention $0 \leqslant B < A$ of Section 2.2: both $s_{ABg}$ and $s_{BAg} = 1 - s_{ABg}$ are treated as functions of $\mu_{ABg}$, given by a single evaluation of $f_3 (\mu_{ABg})$; correspondingly, both logarithmic derivatives are taken with respect to $\mu_{ABg}$ (note that $\partial \log s_{BAg} / \partial \mu_{ABg}$ differs by a sign from the quantity defined via $\mu_{BAg}$ in Section 5.1). The contribution of each atom pair $(A, B)$ to the two accumulators is

  $$
  \begin{aligned}
  \frac{\partial Z_g}{\partial R_{At}} &\mathrel{+}= \Big( P_{Ag} \frac{\partial \log s_{ABg}}{\partial \mu_{ABg}} + P_{Bg} \frac{\partial \log s_{BAg}}{\partial \mu_{ABg}} \Big) \frac{\partial \mu_{ABg}}{\partial R_{At}} \quad (\text{role A}) \\
  \frac{\partial \bar P_g}{\partial R_{At}} &\mathrel{+}= \Big( \delta_{A A_g} P_{Ag} \frac{\partial \log s_{ABg}}{\partial \mu_{ABg}} + \delta_{B A_g} P_{Bg} \frac{\partial \log s_{BAg}}{\partial \mu_{ABg}} \Big) \frac{\partial \mu_{ABg}}{\partial R_{At}} \quad (\text{role A})
  \end{aligned}
  $$

  The two role B formulas have the same shape: simply replace $(A, t)$ by $(B, t)$ and swap in the role B derivatives as the chain-rule factors (the parenthesized coefficients are unchanged). The coefficients in the two formulas correspond to the program variables `common_Z` and `common_Pg`; the $\delta_{A A_g}$ and $\delta_{B A_g}$ indicate that the numerator receives contributions only from the $P$ of the generating atom $A_g$, which in the program is realized by the choice of `LaneAttrib` (`ByGrid` masks per lane, `ByAtom` determines the atom).

- **Two-pass structure**. The running product $P_{M g}$ and the distances $\Vert r \Vert_{A g}$ must be fully generated before they can enter the derivative computation (the formula of Section 5.1 takes the complete $P_{Mg}$ as a factor); hence the first-order gradients form a second pass of the pair loop after `eval_partition`, and the two passes cannot be merged. The first-order accumulators `dR_Z`/`dR_Pg` are zeroed at the start of each lane.

### 5.3 First-order gradients of the weights

This subsection corresponds to `eval_lane_dw`, which outputs the first-order derivatives of the grid weights, `dw` $\frac{\partial w_g}{\partial R_{At}}$, with dims $(A, t, g)$.

- **Quotient-rule final evaluation**. Applying the quotient rule to $w_g = w_g^{\text{quad}} \bar P_g / Z_g$ and the two intermediate quantities given in Section 5.2:

  $$
  \frac{\partial w_g}{\partial R_{At}} = w_g^{\text{quad}} \left( \frac{1}{Z_g} \frac{\partial \bar P_g}{\partial R_{At}} - \frac{\bar P_g}{Z_g^2} \frac{\partial Z_g}{\partial R_{At}} \right)
  $$

- **Translational-invariance correction**. The formula above is the partial derivative under the “$\boldsymbol{r}_g$ independent” convention; following the discussion of Section 4, the derivative of grid $g$ with respect to its generating atom $A$ must be replaced, via the corollary of translational invariance, by the total-derivative result:

  $$
  \frac{\partial w_g}{\partial R_{A_g t}} = - \sum_{M \neq A_g} \frac{\partial w_g}{\partial R_{M t}}
  $$

  The program implements this in two steps: first accumulate the negative row sum $\texttt{dw\_neg\_sum}_t = - \sum_M \frac{\partial w_g}{\partial R_{Mt}}$, then write it back into the generating atom's row (since the remaining rows are all correct, the write-back is equivalent to `dw[A_g, t] += dw_neg_sum[t]`). The write-back method depends on `AtmIndices`: under `ByAtom`, the generating atom is fixed for all the floats of a lane, so a whole-register row update is performed; under `ByGrid`, the update proceeds float by float.

## 6. Program implementation of the Becke partition second-order gradients

The second-order gradients share the same input quantities and pair-loop framework as the first-order ones (Section 5), and the subsection organization parallels that of Section 5: 6.1 gives the mathematical preparation for the second derivatives of the running product, 6.2 corresponds to the second-order part of `eval_switch_pair_pass` (per-pair accumulation), and 6.3 corresponds to `eval_lane_ddw` (final evaluation). But second order is not a mere repetition of first order: the appearance of the rank-1 cross term changes the division of labor between the pair loop and the final evaluation (see the end of 6.1). In the program, the second-order machinery runs only when second-order outputs are requested (`ddw` or its contraction `ddc`) (`do_deriv2`).

### 6.1 Second derivatives of the running product $P_{Mg}$

The argument pattern of 5.1 carries over directly to second order. Differentiating $\log P_{Mg} = \sum_{N \neq M} \log s_{MNg}$ once more:

$$
\frac{\partial^2 \log P_{Mg}}{\partial R_{At} \partial R_{Bs}} = \sum_{N \neq M} \frac{\partial^2 \log s_{MNg}}{\partial R_{At} \partial R_{Bs}}
$$

The second derivative of each switch factor is given by the chain rule (see Section 3 for the explicit expressions of the logarithmic derivatives):

$$
\frac{\partial^2 \log s_{MNg}}{\partial R_{At} \partial R_{Bs}} = \frac{\partial^2 \log s_{MNg}}{\partial \mu_{MNg}^2} \frac{\partial \mu_{MNg}}{\partial R_{At}} \frac{\partial \mu_{MNg}}{\partial R_{Bs}} + \frac{\partial \log s_{MNg}}{\partial \mu_{MNg}} \frac{\partial^2 \mu_{MNg}}{\partial R_{At} \partial R_{Bs}}
$$

Differentiating the basic formula of 5.1, $\partial P_{Mg} = P_{Mg}\, \partial \log P_{Mg}$, once more (product rule) yields the basic second-order formula:

$$
\frac{\partial^2 P_{Mg}}{\partial R_{At} \partial R_{Bs}} = P_{Mg} \left( \frac{\partial^2 \log P_{Mg}}{\partial R_{At} \partial R_{Bs}} + \frac{\partial \log P_{Mg}}{\partial R_{At}} \frac{\partial \log P_{Mg}}{\partial R_{Bs}} \right)
$$

The two advantages stated in 5.1 equally hold at second order: $P_{Mg}$ still appears only as a multiplicative factor, and the per-pair structure still allows direct contraction. But second order brings one additional **structural change**:

- **The rank-1 cross term spans pairs**. $\partial^2 \log P_{Mg}$ is pairwise additive (each $N$ contributes individually, with no crossing); but the second term $\partial \log P_{Mg} \otimes \partial \log P_{Mg}$ is the square of one and the same summation, whose expansion contains products of factors from **different atom pairs** $(N \neq N')$. It cannot be folded into the per-pair pair loop; it must be supplied uniformly at the final-evaluation stage, after $\partial \log P_{Mg}$ has been fully generated.

This dictates a division of labor different from first order: the pair loop (Section 6.2) stores the first-order logarithmic derivatives and accumulates the per-pair parts; the final evaluation (Section 6.3) supplies the cross term and then applies the quotient rule. Correspondingly, first order (Section 5.2) need not store $\partial \log P_{Mg}$ (it is discarded right after contraction), whereas second order must store it (c.f. `dR_log_P`) — this is also the main source of the $O(n_\mathrm{atm}^2)$ memory footprint of the second-order lane scratch.

### 6.2 Computation of important intermediates for second-order gradients

| Variable | Formula | Meaning | Dims | Owner |
|--|--|--|--|--|
| `PrM` | $\mathrm{Proj} (\boldsymbol r_{M}) / \Vert r \Vert_{Mg}$ | Projection matrix of the unit vector along the grid direction | $(M, t, s)$ | `LaneScratch` |
| `dR_log_P` | $\partial \log P_{Mg} / \partial R_{Ct}$ | First-order logarithmic derivative of the running product | $(M, C, t)$ | `LaneScratch` |
| `ddmu_log_sA` | $\partial^2 \log s_{ABg} / \partial \mu_{ABg}^2$ | Second-order switch logarithmic derivative | | temporary |
| `ddmu_log_sB` | $\partial^2 \log s_{BAg} / \partial \mu_{ABg}^2$ | Second-order switch logarithmic derivative (opposite side) | | temporary |
| `ddR_mu_roleAA` | $\partial^2 \mu_{ABg} / \partial R_{At} \partial R_{As}$ (role AA) | Second-order role derivative of the ellipsoidal coordinate | | temporary |
| `ddR_mu_roleAB` | $\partial^2 \mu_{ABg} / \partial R_{At} \partial R_{Bs}$ (role AB) | Same as above; role BA is its $(t, s)$ transpose | | temporary |
| `ddR_mu_roleBB` | $\partial^2 \mu_{ABg} / \partial R_{Bt} \partial R_{Bs}$ (role BB) | Same as above | | temporary |

| `ddR_Pg` | $\partial^2 \bar P_g / \partial R_{At} \partial R_{Bs}$ | Second derivative of the grid partition numerator (as of the end of the pair loop, cross term not included) | $(A, t, B, s)$ | `LaneScratch` |

This subsection corresponds to the second-order part of `eval_switch_pair_pass`; for the first-order quantities that are reused (`dR_dist`, `dmu_log_sA/B`, the first-order role derivatives, etc.), see the table in Section 5.2. The second-order per-pair accumulation is merged with the first-order accumulation of 5.2 into one and the same pair loop: they traverse the same $(A, B)$ pairs, and under deriv 2 a single switch evaluation yields $f_3, f_3', f_3''$. The operations to perform include

- **Second-order role derivatives of the ellipsoidal coordinate `ddR_mu_roleAA/AB/BB`**. Let $f = \Vert r \Vert_{Ag} - \Vert r \Vert_{Bg}$ and $g = \Vert R \Vert_{AB}$ ($\mu = f / g$), and rewrite the componentwise first derivatives of Section 5.2 in vector form (the components of the unit vector $\boldsymbol r_A = (\boldsymbol R_A - \boldsymbol r_g) / \Vert r \Vert_{Ag}$ are precisely $\Vert \partial r \Vert_{Atg}$, and likewise for $\boldsymbol R_{AB}$):

  $$
  \frac{\partial \mu}{\partial \boldsymbol R_A} = \frac{\boldsymbol r_A - \mu \boldsymbol R_{AB}}{\Vert R \Vert_{AB}}, \qquad \frac{\partial \mu}{\partial \boldsymbol R_B} = \frac{-\boldsymbol r_B + \mu \boldsymbol R_{AB}}{\Vert R \Vert_{AB}}
  $$

  The second derivatives are given by the general quotient-rule formula:

  $$
  \frac{\partial^2 (f / g)}{\partial X \partial Y} = \frac{f_{XY} g - (f_X g_Y + g_X f_Y) - f g_{XY}}{g^2} + \frac{2 f\, g_X g_Y}{g^3}
  $$

  The two differentiation directions $X, Y$ each fall on either the left endpoint ($\boldsymbol R_A$) or the right endpoint ($\boldsymbol R_B$) of $\mu$, giving four role combinations in total; the values of $(f_X, f_Y, f_{XY}, g_X, g_Y, g_{XY})$ for each role are as follows (write $\mathrm{Proj} (\boldsymbol v) = \mathbf{I} - \boldsymbol v \boldsymbol v^{\mathsf T}$):

  | role | $f_X$ | $f_Y$ | $f_{XY}$ | $g_X$ | $g_Y$ | $g_{XY}$ |
  |---|---|---|---|---|---|---|
  | AA | $\boldsymbol r_A$ | $\boldsymbol r_A$ | $\mathrm{Proj} (\boldsymbol r_A) / \Vert r \Vert_{Ag}$ | $\boldsymbol R_{AB}$ | $\boldsymbol R_{AB}$ | $\mathrm{Proj} (\boldsymbol R_{AB}) / \Vert R \Vert_{AB}$ |
  | AB | $\boldsymbol r_A$ | $-\boldsymbol r_B$ | $\boldsymbol 0$ | $\boldsymbol R_{AB}$ | $-\boldsymbol R_{AB}$ | $-\mathrm{Proj} (\boldsymbol R_{AB}) / \Vert R \Vert_{AB}$ |
  | BB | $-\boldsymbol r_B$ | $-\boldsymbol r_B$ | $-\mathrm{Proj} (\boldsymbol r_B) / \Vert r \Vert_{Bg}$ | $-\boldsymbol R_{AB}$ | $-\boldsymbol R_{AB}$ | $\mathrm{Proj} (\boldsymbol R_{AB}) / \Vert R \Vert_{AB}$ |

  Here $\mathrm{Proj} (\boldsymbol r_M) / \Vert r \Vert_{Mg}$ depends only on atom $M$ and is precomputed once per lane (`PrM`); $\mathrm{Proj} (\boldsymbol R_{AB}) / \Vert R \Vert_{AB}$ is computed per pair. Role BA and role AB are transposes of each other in $(t, s)$ and are not computed separately. The program implementation is a direct substitution of the table above (c.f. `d2mu` in `eval_switch_pair_pass`).

- **Storage of the first-order logarithmic derivatives `dR_log_P`**. Unlike first order (Section 5.2), $\partial \log P_{Mg} / \partial R_{Ct}$ is no longer discarded after contraction but must be stored in full for the cross term of Section 6.3. The writes for each atom pair $(A, B)$ are

  $$
  \frac{\partial \log P_{Ag}}{\partial R_{Ct}} \mathrel{+}= \frac{\partial \log s_{ABg}}{\partial \mu_{ABg}} \frac{\partial \mu_{ABg}}{\partial R_{Ct}}, \qquad \frac{\partial \log P_{Bg}}{\partial R_{Ct}} \mathrel{+}= \frac{\partial \log s_{BAg}}{\partial \mu_{ABg}} \frac{\partial \mu_{ABg}}{\partial R_{Ct}} \qquad (C \in \{A, B\})
  $$

- **Per-pair L2 accumulation `ddR_Z`/`ddR_Pg`**. According to the basic formula of Section 6.1, the pairwise-additive part of $\partial^2 P_{Mg}$ is $P_{Mg}\, \partial^2 \log P_{Mg}$; the contribution of each atom pair $(A, B)$ to the two accumulators (the role AA block) is

  $$
  \begin{aligned}
  \frac{\partial^2 Z_g}{\partial R_{At} \partial R_{As}} &\mathrel{+}= \Big( P_{Ag} \frac{\partial^2 \log s_{ABg}}{\partial \mu_{ABg}^2} + P_{Bg} \frac{\partial^2 \log s_{BAg}}{\partial \mu_{ABg}^2} \Big) \frac{\partial \mu_{ABg}}{\partial R_{At}} \frac{\partial \mu_{ABg}}{\partial R_{As}} \\
  &\quad + \Big( P_{Ag} \frac{\partial \log s_{ABg}}{\partial \mu_{ABg}} + P_{Bg} \frac{\partial \log s_{BAg}}{\partial \mu_{ABg}} \Big) \frac{\partial^2 \mu_{ABg}}{\partial R_{At} \partial R_{As}}
  \end{aligned}
  $$

  $$
  \begin{aligned}
  \frac{\partial^2 \bar P_g}{\partial R_{At} \partial R_{As}} &\mathrel{+}= \Big( \delta_{A A_g} P_{Ag} \frac{\partial^2 \log s_{ABg}}{\partial \mu_{ABg}^2} + \delta_{B A_g} P_{Bg} \frac{\partial^2 \log s_{BAg}}{\partial \mu_{ABg}^2} \Big) \frac{\partial \mu_{ABg}}{\partial R_{At}} \frac{\partial \mu_{ABg}}{\partial R_{As}} \\
  &\quad + \Big( \delta_{A A_g} P_{Ag} \frac{\partial \log s_{ABg}}{\partial \mu_{ABg}} + \delta_{B A_g} P_{Bg} \frac{\partial \log s_{BAg}}{\partial \mu_{ABg}} \Big) \frac{\partial^2 \mu_{ABg}}{\partial R_{At} \partial R_{As}}
  \end{aligned}
  $$

  The remaining three role blocks (AB, BA, BB) have the same shape: just replace the two chain-rule factors and $\partial^2 \mu$ with the quantities of the corresponding role; the parenthesized coefficients are unchanged. The coefficients of the two formulas correspond to the program variables `common_Z`/`common_dd` and `c1_Pg`/`cdd_Pg`; the $\delta$ selection is the same as in Section 5.2 and is realized by `LaneAttrib`.

- **Zero-initialization discipline**. In the above accumulation, the diagonal blocks (the $C = M$ columns of row $M$, and the $(A, A)$ and $(B, B)$ blocks of `ddR_Z`/`ddR_Pg`) receive contributions from several pairs and are zeroed per lane before accumulating; the off-diagonal blocks receive contributions from a unique atom pair only and are assigned directly. Hence only $O(n_\mathrm{atm})$ diagonal elements need to be zeroed per lane; the $O(n_\mathrm{atm}^2)$ off-diagonal blocks are overwritten by their unique writers and need not be zeroed as a whole.

### 6.3 Second-order gradients of the weights

This subsection corresponds to `eval_lane_ddw`, which outputs the second-order derivatives of the grid weights, `ddw` $\frac{\partial^2 w_g}{\partial R_{At} \partial R_{Bs}}$, with dims $(A, t, B, s)$ (row-major `[natm, 3, natm, 3, ngrids]`).

- **Cross-term completion (rank-1 matrix)**. At the end of Section 6.2, `ddR_Z`/`ddR_Pg` already contain all the pairwise content of $\partial^2 \log P$; what is still missing is the rank-1 term pointed out at the end of Section 6.1. For $Z_g$ it is the matrix

  $$
  C_{At, Bs} = \sum_M P_{Mg} \frac{\partial \log P_{Mg}}{\partial R_{At}} \frac{\partial \log P_{Mg}}{\partial R_{Bs}}
  $$

  (symmetric: $C_{At, Bs} = C_{Bs, At}$). For $\bar P_g$, the rank-1 term has only the single term $M = A_g$, namely $\bar P_g \frac{\partial \log P_{A_g g}}{\partial R_{At}} \frac{\partial \log P_{A_g g}}{\partial R_{Bs}}$ (the program collects the $A_g$ row of `dR_log_P` as `dlog_Ag`). After completion, these are the complete $\frac{\partial^2 Z_g}{\partial R_{At} \partial R_{Bs}}$ and $\frac{\partial^2 \bar P_g}{\partial R_{At} \partial R_{Bs}}$.

  :::{admonition} Implementation decision: tiled computation of the cross-term rank-1 matrix
  :class: note

  Each output element of $C$ requires a summation over $M$, while `dR_log_P` amounts in total to $(3 n_\mathrm{atm})^2$ `f64simd` registers (about 58 KB for $n_\mathrm{atm} = 10$), which exceeds the L1 cache. The program computes in tiles of $12 \times 12$ `f64simd` (`CROSS_CB`): the accumulator of each tile is about $12 \times 12 \times 8 \times 8\,\mathrm{B} \approx 9$ KB and stays resident in L1; the rows of `dR_log_P` are instead read in a streaming manner, and the number of re-reads drops from once per output row to once every $12$ rows. Exploiting the symmetry of $C$, only the upper-triangular tiles are computed and stored mirrored.
  :::

- **Quotient-rule final evaluation**. Let $q_g = \bar P_g / Z_g$ (**used in this subsection only**; $w_g = w_g^{\text{quad}} q_g$); the quotient rule gives

  $$
  \frac{\partial^2 w_g}{\partial R_{At} \partial R_{Bs}} = w_g^{\text{quad}} \left\{ \frac{1}{Z_g} \left[ \frac{\partial^2 \bar P_g}{\partial R_{At} \partial R_{Bs}} - \frac{\partial q_g}{\partial R_{Bs}} \frac{\partial Z_g}{\partial R_{At}} - q_g \frac{\partial^2 Z_g}{\partial R_{At} \partial R_{Bs}} \right] - \frac{1}{Z_g} \frac{\partial q_g}{\partial R_{At}} \frac{\partial Z_g}{\partial R_{Bs}} \right\}
  $$

  where $\frac{\partial q_g}{\partial R_{At}} = \frac{1}{Z_g} \frac{\partial \bar P_g}{\partial R_{At}} - \frac{\bar P_g}{Z_g^2} \frac{\partial Z_g}{\partial R_{At}}$, i.e., the bracketed content of the quotient rule in Section 5.3 divided by $w_g^{\text{quad}}$.

- **Translational-invariance correction**. The formula above is the partial derivative under the “$\boldsymbol r_g$ independent” convention (`ddw_partial`); following Section 4 and the additional remark at its end, the rows, columns, and corner must be replaced by total derivatives:

  $$
  \frac{\partial^2 w_g}{\partial R_{A_g t} \partial R_{Bs}} = - \sum_{M \neq A_g} \frac{\partial^2 w_g}{\partial R_{Mt} \partial R_{Bs}}, \qquad
  \frac{\partial^2 w_g}{\partial R_{At} \partial R_{A_g s}} = - \sum_{N \neq A_g} \frac{\partial^2 w_g}{\partial R_{At} \partial R_{Ns}}
  $$

  $$
  \frac{\partial^2 w_g}{\partial R_{A_g t} \partial R_{A_g s}} = \sum_{M \neq A_g} \sum_{N \neq A_g} \frac{\partial^2 w_g}{\partial R_{Mt} \partial R_{Ns}}
  $$

  During the element-wise scan of the quotient rule, the program incidentally accumulates three sums: `fullA`$[B, t, s] = \sum_A$, `fullB`$[A, t, s] = \sum_B$, and `fullAB`$[t, s] = \sum_{A, B}$; the row correction is $-\,$`fullA`$[B, t, s] + \texttt{ddw\_partial}[A_g t, B s]$, the column correction is $-\,$`fullB`$[A, t, s] + \texttt{ddw\_partial}[A t, A_g s]$, and the corner is `fullAB`$[t, s] - \,$`fullA`$[A_g] - \,$`fullB`$[A_g] + \texttt{ddw\_partial}[A_g t, A_g s]$ (the uncorrected partial values involve only the correct rows and columns and can be reused directly). The `ByAtom`/`ByGrid` differences are as in Section 5.3.

- **Verification**. First, the Hessian symmetry $\frac{\partial^2 w_g}{\partial R_{At} \partial R_{Bs}} = \frac{\partial^2 w_g}{\partial R_{Bs} \partial R_{At}}$; second, the row- and column-sum identities implied by translational invariance, $\sum_A \frac{\partial^2 w_g}{\partial R_{At} \partial R_{Bs}} = 0$ (the same holds for the index $B$); third, comparison with a central difference of the first-order gradients,

  $$
  \frac{\partial^2 w_g}{\partial R_{At} \partial R_{Bs}} \simeq \frac{1}{2h} \left[ \frac{\partial w_g}{\partial R_{Bs}} \Big|_{R_{At} + h} - \frac{\partial w_g}{\partial R_{Bs}} \Big|_{R_{At} - h} \right]
  $$

  The deviation is mainly dominated by the truncation error $O(h^2)$ of the difference.
